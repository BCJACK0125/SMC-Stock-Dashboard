# SMC 股票分析儀表板

用 Python + yfinance 計算 Smart Money Concepts（市場結構 BOS/CHoCH、Order Block、
Fair Value Gap、流動性池、溢價/折價區），畫成互動式 K 線圖並產出靜態網頁，
透過 GitHub Actions 每日自動更新並在訊號分數過高時寄信通知。

## 目錄結構

```
smc-stock-dashboard/
├── smc/
│   ├── __init__.py
│   └── analyzer.py        # 階段一：SMC 核心演算法
├── plot_report.py          # 階段二：Plotly 繪圖 + index.html 產生
├── notifier.py              # 階段三：評分機制 + Gmail 寄信
├── main.py                  # 主流程（本機測試 / GitHub Actions 都跑這支）
├── config.py                # 股票清單、參數、警報門檻設定
├── requirements.txt
└── .github/workflows/update_stocks.yml   # 排程設定
```

## 本機測試

```bash
pip install -r requirements.txt
python main.py --dry-run     # 只產生 index.html，不寄信
open index.html              # 或直接用瀏覽器打開檢查
```

先確認：
1. `config.py` 裡的 `WATCHLIST` 是你想追蹤的股票（台股記得加 `.TW` / `.TWO`）。
2. 圖表、分數、位階看起來合理，再進行下一步部署。

## 部署到 GitHub Pages + Actions

### 1. 建立 Gmail 應用程式密碼（App Password）
不要用 Gmail 登入密碼，Google 已停用「較不安全應用程式」存取：
1. 前往 Google 帳戶 → 安全性 → 開啟「兩步驟驗證」
2. 安全性 → 應用程式密碼 → 建立一組給「郵件」用的 16 碼密碼
3. 複製下來，等一下會貼到 GitHub Secrets

### 2. 設定 GitHub Secrets
到你的 repo → Settings → Secrets and variables → Actions → New repository secret，新增：

| Secret 名稱 | 內容 |
|---|---|
| `GMAIL_SENDER` | 你的 Gmail 帳號，例如 `you@gmail.com` |
| `GMAIL_APP_PASSWORD` | 上一步產生的 16 碼應用程式密碼 |
| `ALERT_RECIPIENT` | 收信信箱（可以跟 GMAIL_SENDER 相同） |

### 3. 開啟 GitHub Pages
Settings → Pages → Build and deployment → Source 選 `Deploy from a branch`，
Branch 選你 push 這個 repo 的分支（例如 `main`）＋ 目錄選 `/ (root)`。
之後每次 Actions 把新的 `index.html` push 回這個分支，Pages 就會自動重新部署。

### 4. 確認排程設定
`.github/workflows/update_stocks.yml` 預設在 **每天 UTC 10:00（台北時間 18:00）** 執行。
也可以到 repo 的 Actions 分頁，手動點 `Run workflow` 立刻測試一次（不用等排程時間）。

## 你可能想接著調整的地方

- **調整訊號權重／門檻**：`notifier.py` 的 `score()`、`config.py` 的 `ALERT_THRESHOLD`。
  目前評分滿分 100，拆成三塊：SMC 結構 60 分、技術指標共振 20 分、輕量 ML
  模型機率 20 分，權重都在 `notifier.py` 檔頭的註解跟 `config.py` 裡可調。
- **調整 swing 靈敏度**：`config.py` 的 `SWING_LOOKBACK`，數字越大代表只抓「大格局」的
  swing，雜訊（假訊號）越少，但反應會比較慢。
- **多時間框架（HTF 定方向、LTF 找進場）**：目前為求 GitHub Actions 排程穩定性，
  全部使用同一個時間框架（目前設定為 4H，由小時線 resample 而來）。如果要做真正
  的多時間框架分析，可以另外對同一標的抓日線資料再跑一次 `SMCAnalyzer`，
  再把兩者的分數加權合併。
- **Order Block 定義更嚴謹版本**：目前用「造成突破的最後一根反向K棒」的最寬區間
  （含影線）當作 OB，你也可以改成只用實體(body)範圍，或加上「該K棒之後必須
  有一段強勢位移（displacement）」的條件，減少雜訊 OB。

## 技術指標與 ML 模型（新增）

### 技術指標共振（`indicators.py`）
在 SMC 結構之外，額外算了業界最常拿來做「多指標確認」的經典技術指標：
RSI(14)、MACD(12,26,9)、EMA(20/50/200)、ADX+DI(14)、ATR(14)、OBV。
評分邏輯只在 RSI/MACD/均線排列/ADX+DI 的方向「一致」時才加分，且 ADX 未過
`ADX_TREND_THRESHOLD`(預設20，代表盤整、沒有值得跟的趨勢)時，DI方向那項不計分。
圖表下方也會多一張 RSI/MACD 副圖，方便你肉眼覆核分數是怎麼來的，而不是只信
一個黑盒子數字。

**誠實的免責提醒**：多篇學術研究（含針對台股/恆生/日經的實證論文）指出，單獨
使用 RSI 或 MACD 長期不必然顯著贏過單純的 buy-and-hold。這裡把它們當成
「跟 SMC 結構訊號互相驗證的濾網」，而不是宣稱這些指標本身有穩定的超額報酬。

### 輕量 ML 模型（`ml_model.py`）
用 `scikit-learn` 的 `GradientBoostingClassifier`，每次 GitHub Actions 執行時
用當下抓到的歷史資料**現場重新訓練**，預測「未來 `ML_HORIZON_BARS` 根K棒後，
收盤價是否上漲」的機率，機率偏離 50% 越多，加分越多（上限 20分）。

選這個模型是因為：GitHub Actions 免費 runner 只有 CPU、沒有 GPU，執行時間也
有限制；多篇量化實證研究（Indonesia/Poland/Korea 股市）都顯示梯度提升樹
（Gradient Boosting / XGBoost 系列）在「股價方向分類」任務上，是 CPU 訓練
最快、實務中相對穩定的模型類型，複雜度遠低於 LSTM 等深度學習模型，
也不需要另外存模型權重（每次都重新訓練，架構最單純、不會有版本漂移問題）。

**局限（務必知道）**：訓練樣本通常只有幾百到一千多筆、每天重新訓練，模型容易
overfit，今天的機率跟明天可能差異不小，本身不構成穩定的預測能力保證。
資料量不足（`ML_MIN_TRAIN_ROWS`，預設80筆）或標籤嚴重失衡時，程式會自動
不給這項分數，而不是硬產生一個不可靠的數字。

相關參數都在 `config.py`：`ML_ENABLED`、`ML_HORIZON_BARS`、`ML_MIN_TRAIN_ROWS`、
`ADX_TREND_THRESHOLD`。

## Walk-forward 回測與自適應門檻（新增）

### 這在解決什麼問題
不同股票的「個性」差異很大——高波動的成長股 vs 低波動的權值股/ETF，同一個
綜合分數門檻（例如固定 60 分）在不同標的上代表的意義完全不同。與其全部標的
共用一個寫死的門檻，`backtest.py` 會在**每次排程執行時**，對每一檔標的分別
回測「這套評分邏輯過去表現如何」，再各自推薦一個「入場次數 vs 勝率」平衡後
的門檻。

### 方法論：Walk-forward Validation（業界公認的回測金標準）
查了 Robert Pardo 提出、業界公認為回測「金標準」的 walk-forward
analysis，核心精神是「參數只能用過去資料決定，永遠不能偷看未來」。
`backtest.py` 的實作方式：

1. 對歷史上每一根K棒 t（跳過前面的暖身期），只用「t 當下已經可以確認」的
   資訊去算 bull_score / bear_score——包含 swing 需要等右側 N 根K棒才能
   確認（原本的 SMC 演算法已經一併修正這個因果性問題，見下方說明）、
   Order Block / FVG 是否已緩解、ADX 等技術指標，全部都只看過去。
2. 用 t 之後第 `BACKTEST_HORIZON_BARS` 根K棒的實際報酬，判斷「如果那時候
   進場，是贏還輸」。
3. 對一組候選門檻（`BACKTEST_CANDIDATE_THRESHOLDS`）分別統計出現次數與勝率，
   在「樣本數 ≥ `BACKTEST_MIN_TRADES`」且「**勝率的 Wilson 95% 下界** ≥
   `BACKTEST_TARGET_WIN_RATE`」的門檻中，選訊號最多（門檻最寬鬆）的那個，
   這就是「入場次數 vs 勝率」的平衡點。沒有門檻達標時，退而求其次選下界
   最高的，並標記為低信心；連樣本數都不夠時，回退到全域預設
   `ALERT_THRESHOLD`，並標記為資料不足。

### 為什麼判準是「期望值」而不是「勝率」

勝率單獨看會騙人，因為它完全沒有考慮**賠率**（平均獲利 ÷ 平均虧損）。
本專案實測到一個具體例子：0050.TW 的多方訊號勝率 59.1%，是五檔標的裡
最高的，但賠率只有 0.54——贏的時候賺一點、輸的時候虧兩倍，結果是
**每筆平均虧 0.75%**。舊版用勝率挑門檻，會很有信心地推薦這個穩定虧錢
的設定。

所以挑門檻的判準改成**扣除交易成本後的期望值**：

```
期望值 = 勝率 × 平均獲利 − (1 − 勝率) × 平均虧損
```

配套的三項修正：

1. **不重疊進場**：連續 10 根 K 棒的訊號其實是在賭同一段行情，它們的
   未來報酬高度重疊。舊版把它們計成 10 筆獨立樣本，讓 n 嚴重灌水
   （實測 n 從 295 掉到 93），信賴區間也跟著假性收窄。
2. **扣交易成本**：`config.transaction_cost()` 依標的類型計算來回成本
   （台股一般股票約 0.47%、ETF 約 0.27%、美股約 0.05%）。回測不扣成本，
   等於在衡量一個不存在的策略。
3. **基準率對照**：這段期間隨便挑一根 K 棒做多，勝率本來就有 52.7~58.8%
   （多頭行情的漂移）。報告裡的「超額」欄位扣掉了這個基準，才看得出訊號
   本身到底貢獻了多少。

### 為什麼用「勝率下界」而不是勝率本身

這裡要同時對付兩個會讓回測結果過度樂觀的問題：

- **小樣本雜訊**：8 筆訊號裡贏 5 筆，點估計是 62.5%，看起來不錯——但它的
  95% 信賴區間大約是 [24%, 91%]，跟「完全沒有資訊」差不多。
- **多重比較（selection bias）**：我們掃描十幾個候選門檻、挑歷史表現最好的
  那個，這個「挑選」動作本身就會系統性高估被選中門檻的勝率，樣本越少越嚴重。

所以挑門檻的判準改成 [Wilson score interval](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval#Wilson_score_interval)
的下界（`backtest.wilson_lower_bound`）：樣本數不足時下界會自動被壓低，挑不出
東西時就誠實地標記為低信心，而不是拿一個好看的點估計來充數。

同樣的邏輯套用在期望值上：`expectancy_lb` 是用 **bootstrap 百分位數**算的
平均值下界。之所以不用常態近似的 `mean − z·sem`，是因為單筆交易報酬明顯
右偏、厚尾（少數大賺、多數小輸小贏），常態假設會低估尾部風險。

此外，掃描 N 個門檻挑最好的那個，本身就會系統性高估被選中門檻的績效
（Bailey & López de Prado 的 [Deflated Sharpe Ratio](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)
講的就是這件事）。`BACKTEST_MULTIPLE_TESTING_CORRECTION` 開啟後會用
Šidák 修正把顯著水準除以試驗次數，讓下界跟著變嚴。

當沒有任何門檻能證明正期望值時，系統會回報 `confidence: "no_edge"`，
明確告訴你「這檔標的在這套訊號下看不出優勢」，而不是硬挑一個點估計
好看的門檻。**這是有用的資訊，不該被粉飾掉。**

### 出場邏輯：停損與目標

原本的回測是「進場後固定持有 N 根 K 棒，看收盤價方向對不對」，這等於
把 SMC 最有價值的部分丟掉了——SMC 的核心賣點是**用結構位取得不對稱的
風險報酬比**，而不是猜方向。

`trade_model.py` 依業界 SMC 慣例把訊號轉成一筆完整的交易：

- **停損**放在「訊號失效處」：多單放在進場價下方最近的看漲 Order Block
  下緣，再往外推 `TRADE_STOP_BUFFER_ATR` 倍 ATR（避免被影線掃到）。
  價格跌破這個 OB，代表當初判斷的需求區失守。找不到合適 OB 時退回
  ATR 倍數停損。
- **目標**放在「對向流動性」：多單看上方最近、尚未被掃蕩的 EQH 流動性池
  ——SMC 的邏輯是價格會朝停損單堆積處移動。找不到時退回 R 倍數目標。
- **時間停損**：超過 `TRADE_MAX_HOLDING_BARS` 根還沒觸及停損或目標就平倉。

緩衝距離一律用 ATR 倍數而非固定點數，才能跨標的、跨波動度環境通用。

⚠️ 模擬時的兩個保守假設：同一根 K 棒同時觸及停損與目標時，一律當作
**先觸及停損**（用 OHLC 無法還原日內先後順序，反過來假設會系統性高估
績效）；成交價假設就是停損/目標價，**沒有模擬跳空與滑價**。

> [EXPERIMENTS.md](EXPERIMENTS.md)。** 那份文件刻意保留失敗的假設——

### ⚠️ 目前的實測結論：優勢主要來自出場紀律，不是 SMC 訊號

把交易成本、不重疊進場、基準率對照三者都補上之後，才看得出這件事。
以 5 檔 watchlist 標的、日線 10 年（2433~2514 根）實測，多方：

| 標的 | 訊號期望值 | 基準期望值 | 超額 | 訊號貢獻佔比 |
|---|---|---|---|---|
| 0050.TW | +1.45% | +1.40% | +0.05% | 4% |
| 2317.TW | +2.20% | +0.64% | +1.56% | 71% |
| 2330.TW | +1.56% | +1.67% | −0.11% | −7% |
| AAPL | +2.28% | +1.92% | +0.36% | 16% |
| NVDA | +3.95% | +3.63% | +0.32% | 8% |

「基準」是**每一根 K 棒都進場、套用完全相同的停損與目標**。也就是說，
光是「有紀律地進場 + 結構化停損停利」就已經有 +0.64%~+3.63% 的期望值，
SMC 評分引擎在 5 檔裡的 4 檔只貢獻了 4%~16%。

參數敏感度測試（目標 R × 最長持有，共 8 組）更明確：

- **絕對期望值**在全部 8 組下都是正的（+1.70%~+3.27%）→ 穩健
- **超額**在 −0.85% ~ +0.78% 之間反覆變號 → 被參數選擇淹沒，等於零

這是「沒有可證實優勢」的典型特徵。誠實的結論是：

> 這套系統目前是一個**有效的風險管理框架**（結構化停損讓賠率從 0.54
> 提升到 1.46~1.94），但**不是一個有效的選時系統**。它賺到的主要是
> beta 與出場紀律，不是 SMC 結構分析的預測力。

這不代表 SMC 無效，而是說「目前這組評分規則與權重」還沒有展現出優勢。
下一步應該是拿正確的目標函數（超額期望值）去**擬合評分權重**，而不是
繼續憑感覺配 15/15/10/15/8/7/5/20。

### 以獲利為目標：複利績效與買進持有對照

期望值是**算術平均**，回答不了三個實際問題：一年會有幾筆？複利之後
剩多少？贏不贏「什麼都不做」？`performance.py` 補上這一層。

（+50% 之後 −50% 的算術平均是 0，實際只剩 0.75——波動越大，算術平均
高估得越多。）

單檔日線 10 年實測（多方，已扣來回成本）：

| 標的 | 策略年化 | 策略回撤 | 在場時間 | 買持年化 | 買持回撤 | Calmar 對照 |
|---|---|---|---|---|---|---|
| 0050.TW | +13.9% | 18% | 50% | +25.9% | 34% | 0.77 vs 0.76 ✅ |
| 2317.TW | +11.1% | 18% | 28% | +12.0% | 51% | 0.62 vs 0.23 ✅ |
| 2330.TW | +10.2% | 16% | 32% | +35.6% | 45% | 0.62 vs 0.79 ❌ |
| AAPL | +19.3% | 19% | 50% | +28.8% | 39% | 1.02 vs 0.75 ✅ |
| NVDA | +28.7% | 42% | 41% | +55.1% | 66% | 0.69 vs 0.83 ❌ |

**絕對報酬 0/5 勝，風險調整（Calmar）3/5 勝。**

關鍵不是訊號差，而是**資金有 50~72% 的時間閒置**。單檔策略只在有訊號時
進場，買進持有則是 100% 在場；在一段長期上漲的行情裡，這個在場時間差
幾乎不可能靠每筆多賺一點補回來。

風險調整後能打平甚至勝出，代表訊號品質本身沒問題——問題是**資金效率**。

### 組合層回測（portfolio.py）

解法不是讓單檔更常進場（那會稀釋訊號品質），而是**橫向擴張**：同時追蹤
數十檔標的，任何時刻總有幾檔有訊號，組合的在場時間就能拉高到接近 100%，
而每一筆進場仍維持原本的訊號品質。

`portfolio.py` 模擬「資金平均分配到最多 N 個並存部位」的組合，對照組是
**等權買進持有整個驗證池**（拿組合去比單一檔股票並不公平）。

權益曲線會對未平倉部位**逐根做市價評估**（傳入 `prices`）。這一步不能省：
沒有它的話，部位中途跌 15% 再拉回來完全不會反映在曲線上，最大回撤會被
嚴重低估、Calmar 被高估——而「風險調整後比較好」正是這套系統唯一站得住
的結論，不能建立在這種偏差上。

（測試 `test_mark_to_market_exposes_intra_trade_drawdown` 釘住了這件事：
同一筆交易，不做市價評估時回撤顯示 0%，做了之後顯示 >35%。）

**實測結果（41 檔驗證池、日線 10 年、固定 2R 目標）：**

| 最大同時持倉 | 每年筆數 | 年化 | 最大回撤 | 在場% | Calmar |
|---|---|---|---|---|---|
| 5 | 84 | +12.6% | 24% | 99% | 0.52 |
| 10 | 156 | +12.9% | 18% | 100% | 0.70 |
| 20 | 245 | +10.9% | 14% | 99% | 0.77 |
| 30 | 260 | +9.0% | 11% | 99% | 0.83 |
| **等權買進持有** | — | **+29.2%** | 39% | 100% | 0.75 |

在場時間確實從單檔的 28~50% 拉到了 **99~100%**，但**報酬完全沒有跟上**
——年化只有等權買進持有的三分之一。「資金閒置是主因」這個假設被推翻了。

真正的原因是：**固定目標在趨勢行情裡會砍掉贏家**。買進持有吃到完整的
十年趨勢，這套策略每次只吃 2R 就出場、還要付一次來回成本，一年 84~260
次。虧損那邊有停損保護（回撤 11~24% vs 39%），但獲利那邊也被截斷了，
等於「限制下檔的同時也限制了上檔」。

這也是 `TRADE_EXIT_MODE = "trailing"` 存在的理由：拿掉固定目標，改用
移動停損，讓虧損仍然有限、但獲利不設上限。

### 橫斷面驗證（validate.py）

5 檔標的、單一市場環境，無法區分「策略有效」與「這幾檔剛好」。
`validate.py` 對一個 41 檔、跨產業跨市場的驗證池（`VALIDATION_UNIVERSE`）
跑完整回測，看的是**跨標的的一致性**：

```bash
python validate.py              # 完整驗證池（慢，建議本機跑）
python validate.py --limit 10   # 快速冒煙測試
python validate.py --jobs 4     # 多進程平行
```

關鍵輸出是「有多少比例的標的能證明正期望值」。如果只有 1~2 檔亮燈、
期望值中位數又貼近零，那就是**沒有優勢**的證據，不是「再多調幾個參數
就好」。這支程式跟每日排程分開，不影響 `main.py` 的執行時間。

回測結果（每個門檻的樣本數與勝率、最終建議門檻）會顯示在網頁每檔標的的
圖表卡片上方，也會另外存成 `backtest_results.json`，方便你追蹤這個回測
結果隨時間怎麼變化。寄出的警報信也會附上「這次觸發的門檻，過去回測勝率
多少、樣本數多少」，讓你自己判斷這封信可信度高不高。

### 為了讓回測站得住腳，順手修正的一個因果性 bug
原本 `SMCAnalyzer` 的 swing high/low 用「左右對稱」的 fractal 判斷法——
但這代表判斷「某根K棒是不是 swing」需要看到它右邊 N 根K棒才能確認，
若拿完整歷史資料跑一次，再回頭去看「當時的訊號」，其實已經用了未來資料。
現在每個 `SwingPoint` 多存一個 `confirmed_index`（要等到哪一根K棒才能
真正確認這個 swing），結構事件（BOS/CHoCH）的判斷也改成用這個確認時間
點來決定「這個 swing 現在能不能用」。這個修正同時讓正式網頁上顯示的訊號
時間點更準確，不只是為了回測。

### 誠實的局限（不誇大這個功能的可信度）
- 這是「單一次」樣本外回測，不是更嚴謹的「多段滾動」walk-forward
  optimization（那需要切成好幾段 in-sample/out-of-sample 反覆驗證，
  這裡因為單一標的歷史資料量有限、又要在 GitHub Actions 的時間預算內
  跑完所有標的，所以簡化成一次性、單向的樣本外回測）。
- ML 模型為了控制運算量，每隔 `BACKTEST_ML_RETRAIN_EVERY`（預設10）根K棒
  才重新訓練一次，不是每根都重訓。
- 完全沒有考慮交易成本、滑價、稅務——勝率只是「未來收盤價方向」對不對，
  不是真的下單後的損益勝率。
- 樣本數少的標的（新上市、資料很短、或某個方向訊號本來就很少出現）回測
  本身就不可靠，這也是為什麼要有 `BACKTEST_MIN_TRADES` 門檻、以及網頁上
  「樣本不足」的誠實標示，而不是硬湊一個看起來很高的勝率數字。
- 歷史勝率不保證未來績效。這整套系統的目的是「幫你篩選出訊號歷史上相對
  可信的標的與門檻」，而不是「保證獲利」。
